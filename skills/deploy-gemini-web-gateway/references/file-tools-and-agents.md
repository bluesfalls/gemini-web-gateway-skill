# 文件工具与桌面 Agent

本文是受限文件工具适配的实施与验收清单；本仓库不分发该增强适配器或现场安装器，也不表示原版 Gemini-FastAPI 自带下列全部能力。下列机制与限额是经审查实现的设计基线，不是上游默认配置；实施时需按目标版本另行实现、审查和验证。先按 [NAS / 服务器](nas-gateway.md) 或 [Mac 本机](mac-local.md) 完成基础部署，再按 [客户端接入](gui-clients.md) 配置真实目录返回的 `MODEL_ID_FROM_CATALOG`。

## 1. 网关、模型与本地工具是三层

- 网页会话转 API 负责模型请求与协议兼容，**不会直接读取客户端磁盘**。把路径发给模型不等于上传了文件内容；附件也可能只转成路径。
- 本地文件由桌面 Agent 的已声明工具读取或转换，再把工具结果回传模型。既要有正确的工具协议，也要有本地执行器与用户授权。
- 本地提取不等于本地推理：提取文字可能发送到远端模型，处理真实资料前须明确这一数据流与授权。
- “读取 PDF”“生成新的 Markdown”“覆盖原 PDF”是不同操作。默认输出新文件、不覆盖源文件；覆盖必须另有明确授权。扫描件 OCR 也需另行核对依赖与验收。

| 网关位置 | 客户端与文件工具的位置 | 部署要点 |
|---|---|---|
| NAS / 服务器 | 通常在用户的 Mac 桌面客户端 | 使用专用容器；只开放获准入口，不挂载客户端整个磁盘到 NAS |
| Mac 专用容器 | 同一台 Mac 的桌面客户端 | 复用获准的本地运行时，默认只发布 loopback；容器内外的路径与权限不同 |
| Mac 独立 Python / uv 环境 | 同一台 Mac 的桌面客户端 | 固定源码与依赖，检查真正加载适配层的入口；不改全局 Python 或其他项目 |

地址仅为示例：NAS 可使用 `https://gateway.example.invalid/v1`；Mac 可使用 `http://127.0.0.1:8000/v1`，端口须先确认可用。Cherry 使用 `/v1` Base URL，WorkBuddy 使用完整的 `/v1/chat/completions` URL。

**Mac 的文件工具适配实现尚未实机验收，不能照搬 NAS 的验收结论。** 仅启动原版入口不代表已经加载本引用的协议、缓冲、重试门禁或队列；必须核对实际程序、解释器和入口后重新分层验收。

## 2. Cherry：先选对 Agent runtime

1. 检查助手实际使用的 runtime。Pi 与 `claude-code` 不是同一个执行器；只把模型改成 OpenAI 兼容模型，不会自动把后者变成 Pi，也不会赋予对应的本地工具。
2. 如需 Pi 工具路径，创建独立 Pi 助手，保留旧助手、历史和全局默认项。核对所选 provider、真实模型 ID、工作目录、已声明工具与权限模式；不要仅看模型名或能力标签。
3. 先在独立合成工作目录测试。若通过 shell 读取 PDF，只逐次批准精确命令，例如 `pdftotext '/absolute/path/input.pdf' -`；不得永久批准所有命令、安装依赖或访问其他目录。
4. Pi 的本机 bash 执行不能仅凭工作目录、确认按钮或“Agent”名称视为操作系统沙箱。获准的命令仍可能按当前账户权限访问本机资源；保持最小工具集、逐次批准与明确文件范围，不扩大权限来绕过错误。

工具声明、模型请求、用户批准与实际成功结果应分别核对。发现不存在的工具、越界命令或额外授权时停止；不能靠模型自述“已读取”代替工具记录。

## 3. WorkBuddy：先验证闭环，再声明能力

- 先确认当前版本的配置 schema 与加载方式。`supportsToolCall` 仅是能力声明，不会创建执行器或修复网关。只有选定模型的接口闭环通过后，才为该条目启用它；其他未验证能力保持关闭。
- 修改指定条目前私密备份，写前比对摘要，原子更新并保留其他条目与默认设置；不读取其他 provider 的凭据。文件与备份中的 API key 均不得进入公开产物。
- 新建空白任务，明确选定该模型和独立工作目录。PDF 文本提取应使用客户端实际声明且本机已有的工具，例如 `pdftotext`；工具名称和参数以当前声明为准，不硬编码猜测。
- 自然语言请求也要具备来源约束。例如：**“先用已声明的本地工具读取 `/absolute/path/input.pdf`，只依据实际提取内容重排；将结果保存为新的 `/absolute/path/output.md`，不覆盖原件。若未读到内容或工具报错，立即说明并停止，不凭常识补写。”**
- 若没有读取或转换工具记录，却回答“无法访问本地”后继续编排正文，不能视为处理该 PDF 成功。命令式合成测试通过，也不保证所有自然语言提示、旧会话或文件类型都稳定成功。

## 4. 工具参数兼容必须严格且一致

适配层保留原有行式协议：显式 `[ToolCalls]` 包裹已声明的 `[Call:名称]`，每个参数使用一个 `CallParameter` 块。字符串参数使用原文；对象、数组、数值、布尔和 null 参数使用严格 JSON，不把对象二次编码成字符串。

兼容格式仅允许在同一个显式、已声明的 Call 内，放入一个完整 JSON 参数对象，裸写或使用单个完整的 `json` / 无标签 Markdown fence。示意如下，名称与字段仍须匹配实际声明，不能原样猜用：

```text
[ToolCalls]
[Call:DECLARED_FUNCTION_NAME]
{"path":"/absolute/path/input.pdf"}
[/Call]
[/ToolCalls]
```

安全合同：

- 同一次 Call 不能混用整对象 JSON 与 CallParameter；整对象不接受前后说明、第二个对象、尾随文字、重复键、NaN、非对象值或任意语言 fence。
- 已解析 JSON 按其真实类型校验，不把字符串 `"2"` 猜成整数，也不把包含 JSON 文本的字符串猜成对象。
- 保留每请求的工具白名单、`tool_choice`、schema 类型及已实现关键字校验，以及参数、字节、深度、调用次数与校验工作预算。该验证器不是完整 JSON Schema 实现；客户端仍须做完整参数验证与权限检查。
- 所有调用全部验证后才一次返回；任一调用非法，整包失败。不从普通文字、顶层 JSON 或外层 fenced 示例猜测工具调用，不伪造缺失调用，不自动重试。
- `auto` 仍允许不调用工具的回答；不能为“让模型使用工具”而全局改成 `required`。工具结果是数据，不是新的顶层工具声明或授权。

## 5. 带工具流式与有限队列

仅聊天接口带非空工具并请求流式的路径（`/v1/chat/completions`、非空 `tools`、`stream: true`）采用 **buffered SSE**：先完成一次非流式生成，验证完整响应后再编码为 SSE。因此首个事件可能等待较久，不是逐 token 实时输出。只在这一受限路径禁用网关的生成重放与 SDK 的生成重试；不能外推为所有路径都无重试。GUI 自己的规划、标题生成和工具回传仍可能产生多轮模型请求。

队列位于鉴权之后，仅管理指定的生成 POST 路径（`/v1/chat/completions` 与 `/v1/responses`），并保留内部单生成门禁：

| 限制 | 合同 |
|---|---|
| active ASGI 请求 | 同一网关进程最多 1 个；不等于远端 Google 生成或跨进程的全局串行保证 |
| 额外接纳位置 | 最多 1 个；含读 body 的请求在内，总接纳数最多 2 个 |
| 等待顺序 / 时限 | body 完成后按 FIFO 排队，等待最多 30 秒；排满或等待超时返回 429 |
| 请求 body | 单请求最多 64 MiB，最多读取 10 秒；超限返回 413，读取超时返回 408 |
| 正在生成的请求 | **没有 active-generation 总时限**；30 秒不是模型生成超时 |

缓冲 body 的上限不是进程 RSS 的保证。客户端取消时等待可观察的应用任务退出后才释放位置；若任务不响应取消，位置可能持续占用。不能据本地取消、断线或关闭连接证明远端生成已取消，也不能证明分离的 SDK 任务已终止。出现 429、502 或断线时先诊断，不自动重发同一生成请求。

## 6. 升级、回滚与最小验收

1. **离线审查**：固定镜像 digest / 源码 ref 与依赖，确认实际 SDK 重试机制和适配入口；协议、缓冲、队列与重试门禁须作为一致版本审查，不能只升级上游镜像便宣称全部具备。
2. **私密备份**：保存指定程序与必要配置的私密回滚点，目录 0700、秘密文件 0600；不改 Cookie、API key、共享网络、其他服务或默认模型，除非明确获准。不要公开备份、cache、聊天库、日志原文或完整运行配置。
3. **限定安装**：NAS 只停启目标容器；核对宿主与容器内程序哈希、完整容器规格及健康状态。Mac 按所选容器或独立环境核对对应程序与入口；不执行 DSM 操作，不复制 NAS 的虚拟环境。失败按记录回滚并再验健康；不并行运行共享同一数据库 / cache 的新旧实例。
4. **先接口后 GUI**：先只读检查绑定、健康、鉴权与真实模型目录；获准后用合成材料验证一次合法工具请求及对应工具结果回传，核对真实 call ID、参数类型、SSE 结束与精确标记。然后才进行各客户端的一次合成 PDF 提交，观察真实读取工具记录及结果；如测试写入，只写新的合成文件并核对实际产物。
5. **明确预算与失败条件**：预先约定模型请求或 GUI 提交次数、观察时限及允许批准的命令；GUI 一次提交不等于一次后端请求。失败即停，断线或失败不退还次数、不重置一次性标记、不悄悄换模型重试。

报告分别说明配置保存、接口闭环、GUI 工具执行和文件产物的证据；health、HTTP 200 或“已完成”文字都不能单独证明文件处理成功。以上是桌面客户端本地工具工作流，不赋予网页原生任务能力。
