# 验收与排障判据

## 分层报告，不能跨层推断

| 观测 | 可报告 | 不能据此保证 |
|---|---|---|
| health正常 | 当次进程及被检查依赖正常 | 账户已登录、全部模型可用 |
| 账户状态及独立佐证匹配 | 对应输入/会话当次认证 | 原生Task后端权限、签名和attestation等价 |
| 模型目录 | 该请求返回了这些ID | 网页所有功能已覆盖、不是静态/访客alias |
| chat返回模型ID及精确marker | 最小请求行为符合判据 | 所有提示/长会话/工具任务都正常 |
| SSE有非空delta与DONE | 该次SSE语法/结束符合合同 | 后端异步任务完整终局 |
| BrowserChannel HTTP200/ACK | 传输/确认成功 | 业务成功、产物已生成 |
| 无产物/本地关闭/清理超时 | 客户端未收到或未确认 | 远端未创建、已取消、可安全重试 |

## 低影响只读检查

确定是否需要判断网络、网关认证、账户认证、模型发现或GUI可见性，再取最少证据。只读访问已确认网关的health/models，不发送聊天；限制重定向、时间、体积，日志只保留HTTP状态、布尔项、计数与固定错误码。

故障先区分：工具/沙箱权限、DNS/路由、Docker状态、网关API key、网页账户登录、模型registry、请求schema、业务响应。沙箱的PermissionError不等于NAS宕机；SSH PATH/解释器不匹配不等于Gemini认证失败。

GUI“测试连接”可能实际生成。不要因为按钮叫测试就认为只读；先核实现，再按生成授权处理。界面列表未更新时，刷新相应页面；不要先重启整个应用或中断现有工作。

## 最小生成验收（仅在获准后）

固定提示可以是“只回复 CONNECTION_CHECK_OK”，不带已有消息、system资料或工具；用真实目录ID，限制次数/并发/超时，不自动fallback或retry。先测一个已知适合普通对话的模型，不循环扫全账户模型。

验收分别核对：HTTP状态、返回模型ID、精确marker、SSE非空增量/结束、GUI实际显示。正文不保留时只记录长度/marker匹配，不根据长度或有限关键词断言具体拒答。精确marker失败不等于整个网关坏，也不是成功。

记录“用户提交消息数”和“后端请求数”的区别：GUI可能自动生成标题等附带请求；没测量就写未知，不给出虚假的精确总量。既有聊天与原生Task试验分账，获准次数不能因失败/断线而复位。

## 登录态和模型缺失

- 冷启动的config-only Cookie会话、缓存刷新会话、正在运行的daemon是不同输入；一个未认证不证明另外两个未认证。不要读取daemon内存或自动扫描浏览器Cookie来填补证据。
- HTTP200、初始HTML字段存在、`/app`可打开均不足以证明登录。按**所选版本**的状态RPC与独立账号/套餐证据校验。
- 状态中缺字段、显式null、畸形和整数应区分。某些版本接受显式null或特定整数，不能无条件归一化为成功；未知状态fail-closed并保持原配置。
- 使用已安装库的cache会话作诊断时，复制到私有临时目录，禁止写回/清除正式cache；仅第一明确候选，不轮流尝试更多账户。需要沿用会话的后续操作必须在同一client关闭之前衔接。
- RPC parser报错先比对当前上游framing合同；例如XSSI、UTF-16帧长、前后空白和终局控制帧，不先归罪Cookie。未保留原始敏感响应时，准确说明可验证范围。
- 不以“清单里有某个ID”判断网页任务资格；元数据原始ID字段可能为空，需按当前schema解析variant或base关联，不能编造替代ID。

## 网页原生Task的停止边界

普通 `/v1/chat/completions`、客户端自己的agent编排、网页原生Task是三个接口层。没有经过授权和真实产物/生命周期验收，不添加“Task”假别名，不声称工具执行、调度、文件工作区或完整远端取消已支持。

如果用户另行要求研究原生协议，作为独立项目约定试验范围、计数和确认/权限停止条件。产品advertisement、模型feature枚举与请求模式枚举不一定是同一概念；静态JS子集没观察到签名值，不证明浏览器运行时无签名。

不要把PSID类Cookie冒充SAPISID签名材料，也不伪造/重放attestation或绕过额外挑战。认证未决时保留未决状态，不通过删除头/猜字段后“碰运气重试”掩盖它。

对于明确的单次有副作用试验，在发送前作持久保守预留；失败、超时和输出丢失均不释放。保留标记是一次持久写，不能同时报告“零持久修改”。没有远端取消证据就写未知，新的试验必须有新的明确授权。
